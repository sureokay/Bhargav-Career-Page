HTTP Status Codes

Most Commonly Used Status Codes

Essential HTTP response codes every developer should know

200
Success
OK
The request succeeded. This is the standard response for successful HTTP requests and is the most common status code.
GET /api/users → Returns user data successfully
404
Client Error
Not Found
The server cannot find the requested resource. This is the most well-known error code among end users.
GET /nonexistent-page → Page doesn't exist
500
Server Error
Internal Server Error
The server encountered an unexpected condition that prevented it from fulfilling the request.
Database connection error or unhandled exception
401
Client Error
Unauthorized
The client must authenticate itself to get the requested response. Authentication is required and has failed.
Missing or invalid authentication token
403
Client Error
Forbidden
The client does not have access rights to the content. Server understands the request but refuses to authorize it.
User lacks permission to access admin panel
301
Redirect
Moved Permanently
The URL of the requested resource has been changed permanently. Search engines will update their indexes.
old-domain.com → new-domain.com
400
Client Error
Bad Request
The server cannot process the request due to a client error, such as malformed request syntax or invalid parameters.
Invalid JSON format or missing required fields
302
Redirect
Found (Temporary Redirect)
The URI of the requested resource has been changed temporarily. Future requests should still use the original URI.
Temporary redirect during maintenance
503
Server Error
Service Unavailable
The server is not ready to handle the request, commonly due to maintenance or temporary overload.
Server maintenance or high traffic overload
201
Success
Created
The request succeeded and a new resource was created as a result. This is typically sent after POST requests.
POST /api/users → New user account created
202
Success
Accepted
The request has been accepted for processing, but the processing has not been completed. Often used for asynchronous operations.
POST /api/batch-process → Processing started, check status later
204
Success
No Content
The server has successfully fulfilled the request and there is no additional content to send in the response payload body.
DELETE /api/users/123 → User deleted, no content returned
206
Success
Partial Content
The server is delivering only part of the resource due to a range header sent by the client. Used for resumable downloads.
GET /video.mp4 Range: bytes=200-1023 → Returns specified byte range
304
Redirection
Not Modified
The resource has not been modified since the version specified by the request headers. The client can use cached version.
GET /api/data If-Modified-Since: Mon, 18 Jun 2025 → Use cached version
307
Redirection
Temporary Redirect
The target resource resides temporarily at a different URI. The client should repeat the request with the same method.
POST /old-endpoint → 307 redirect to /new-endpoint (keeps POST method)
308
Redirection
Permanent Redirect
The target resource has been assigned a new permanent URI. Future requests should use the new URI and the same HTTP method.
PUT /api/v1/users → 308 redirect to /api/v2/users (keeps PUT method)
402
Client Error
Payment Required
Reserved for future use. Originally intended for digital payment systems, now often used to indicate that payment is required to access a resource.
GET /premium-content → Payment required to access this content
405
Client Error
Method Not Allowed
The request method is known by the server but is not supported by the target resource. The server must include an Allow header.
DELETE /api/users → Method not allowed, only GET, POST supported
406
Client Error
Not Acceptable
The target resource does not have a current representation that would be acceptable to the user agent, according to the proactive negotiation header fields.
GET /api/users Accept: application/xml → Only JSON available, not XML
408
Client Error
Request Timeout
The server did not receive a complete request message within the time that it was prepared to wait. Client may repeat the request.
POST /api/upload → Request took too long, connection timed out
409
Client Error
Conflict
The request could not be completed due to a conflict with the current state of the target resource. Often occurs with concurrent modifications.
PUT /api/users/123 → Conflict: User was modified by another request
410
Client Error
Gone
The target resource is no longer available at the origin server and this condition is likely to be permanent. Unlike 404, this implies the resource existed before.
GET /api/deprecated-endpoint → Resource permanently removed
411
Client Error
Length Required
The server refuses to accept the request without a defined Content-Length header. The client may repeat the request with a valid Content-Length.
POST /api/upload → Content-Length header required for this request
412
Client Error
Precondition Failed
One or more conditions given in the request header fields evaluated to false when tested on the server. Used with conditional requests.
PUT /api/users/123 If-Match: "abc123" → ETag doesn't match current version
413
Client Error
Payload Too Large
The server is refusing to process a request because the request payload is larger than the server is willing or able to process.
POST /api/upload → File size exceeds 10MB limit
414
Client Error
URI Too Long
The server is refusing to service the request because the request-target is longer than the server is willing to interpret.
GET /api/search?q=very-long-query... → URL exceeds maximum length
415
Client Error
Unsupported Media Type
The server does not support the media format of the requested data, so the server is rejecting the request.
POST /api/data Content-Type: text/csv → Only JSON supported, not CSV
418
Client Error
I'm a teapot
This code was defined in RFC 2324 as an April Fools' joke. The server refuses the attempt to brew coffee with a teapot. Sometimes used humorously by APIs.
POST /brew-coffee → I'm a teapot, cannot brew coffee!
422
Client Error
Unprocessable Entity
The server understands the content type and syntax of the request, but was unable to process the contained instructions due to semantic errors.
POST /api/users {"email": "invalid-email"} → Valid JSON, invalid email format
429
Client Error
Too Many Requests
The user has sent too many requests in a given amount of time. Rate limiting is in effect. Often includes a Retry-After header.
GET /api/users → Rate limit exceeded: 100 requests per hour
501
Server Error
Not Implemented
The server does not support the functionality required to fulfill the request. This is the appropriate response when the server does not recognize the request method.
PATCH /api/users → PATCH method not implemented on this server
502
Server Error
Bad Gateway
The server, while acting as a gateway or proxy, received an invalid response from an inbound server it accessed while attempting to fulfill the request.
GET /api/external-data → Upstream server returned invalid response
